# 临床数据收集系统

`clinical-data-system` 是面向临床研究资料收集、PDF 资料审阅、整改闭环和资料包智能识别的内部业务系统。

系统当前进入 `V3.3.0 试验方案解析与项目配置初始化模块`：`V3-P0` 的 PDF 资料包切分、人工校正和确认闭环已经通过验证，`V3.1.0` 数据看板工作台已形成系统内维护基线；V3.2 系列已补齐试验准备、试验进行、试验结束三大阶段的资料清单、SSU 进展、固定访视阶段、“若有”资料完整性口径和看板展示化能力；本轮在项目管理中新增临床试验方案 PDF 版本留痕、解析预览、人工修正和确认应用能力，用于初始化试验进行阶段访视、资料模板和中心主数据。

## 1. 系统定位

系统围绕临床资料从上传到审核的完整链路建设：

- 项目、中心、阶段、资料模板和字典等基础主数据。
- 受试者资料项管理、资料上传、文件版本和操作日志。
- PDF 在线预览、画框批注、整改任务单和复审闭环。
- PDF 资料包上传、OCR、智能切分、人工拆分/合并/修正、确认并上传入库。
- V3.1.0 数据看板工作台：实验项目 7 张业务表、整体进度预期偏离预警、重要紧急事项完成情况。
- V3.2.1 临床数据集体验修正：试验准备阶段拆分 SSU 进展/资料准备，若有资料需上传或声明无此材料。
- V3.2.2 试验进行阶段资料与访视重构：试验进行阶段拆分资料准备和 V1-V4 固定访视阶段，旧试验阶段迁移到新结构。
- V3.2.3 看板展示化：看板纯展示，手工维护拆到独立入口，并输出数据库字段设计文档。
- V3.3.0 试验方案解析：项目管理常驻上传方案 PDF，解析访视/资料项/中心，预览修正后差异应用到主数据。
- V3.3 后续继续重塑资料分类、板块体系和资料包审核布局。
- 后续字段结构化抽取将在 V3.3 后续分类与布局稳定后再启动。

## 4. 技术栈

- Frontend: React + TypeScript + Vite + Tailwind CSS + lucide-react + PDF.js
- Backend: FastAPI + SQLAlchemy 2.x + Pydantic + Alembic
- Database: PostgreSQL
- OCR:
  - Mac 本地开发：Apple Vision OCR 服务，默认端口 `8048`
  - Linux 生产：PaddleOCR GPU 服务
- Deploy: Docker Compose + Nginx

## 5. 本地开发启动

后端：

```bash
cd backend
source .venv/bin/activate
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```


## 6. 当前测试重点

V3-P0 已完成实际测试，`010005.pdf` 当前基准为：

```text
12 segments, 27 text/OCR pages
```

`010001.pdf` 已用于观察复用性，当前结论是：偏差不属于系统切分闭环失败，而是现有资料分类/板块定义不准确。

V3.1.0 数据看板测试重点：

- 数据看板首页分为“实验项目”和“整体进度计划达成情况”。
- 实验项目支持进度甘特图、入组计划表、整体情况表、器械交接记录表、受试者结果统计表、临床事件记录、器械问题记录表。
- 整体进度支持预期偏离预警和重要紧急事项完成维护。
- 数据看板 V3.1 表格支持列表、筛选、新增、编辑、删除、Excel 模板、导入和导出。
- 生产 OCR GPU 模式不在本版本调整范围内。

V3.2.2 临床数据集测试重点：

- 阶段导航显示“试验准备阶段 / 试验进行阶段 / 试验结束阶段”，内部代码仍保留 `STARTUP/TRIAL/CLOSEOUT`。
- 试验准备阶段展开“SSU进展 / 资料准备”两个子目录，默认进入 SSU 进展，资料准备独立显示 26 项中心级资料。
- 试验进行阶段默认进入“试验实施访视阶段受试者列表”，另有“资料准备”子目录显示第 27-45 项中心级资料。
- 受试者访视阶段固定为 `V1筛选访视阶段`、`V2试验组随访访视`、`V3对照组随访访视（若有）`、`V4非预期访视（若有）`。
- 试验结束阶段直接显示 10 项中心级资料准备。
- 名称含“若有”的资料默认不齐全，需上传审核通过或手动声明“无此材料”后才算齐全。
- 旧试验进行阶段结构已迁移到新固定访视结构，本版不引入 OCR 自动切分。

V3.3.0 试验方案解析测试重点：

- 项目管理可上传临床试验方案 PDF，保存方案版本并解析访视、资料项和中心。
- 解析结果必须先进入预览草稿，支持人工修正后确认应用。
- 确认应用后新增或更新试验进行阶段访视、受试者资料模板和中心主数据，不默认删除旧配置。
- 项目负责人只能维护自己项目范围内的方案版本。

V3.2 后续资料分类测试重点：

- 重新定义资料分类和板块体系。
- 明确板块、资料项、片段、字段之间的关系。
- 调整资料包审核页面布局，让人工审核围绕板块展开。
- 在分类体系稳定后，再继续考虑字段结构化抽取。
